# Product Principles

These principles were distilled from the historical chat-source files and reinforced throughout the current conversation.

## Core Identity
Akivot is not:

- a CRM
- a management system
- a bureaucracy tool

Akivot is:

- peace of mind
- immediate clarity
- calm operational guidance

## Main Principles
1. The product must reduce pressure, not add it.
2. The user should understand what is happening without thinking.
3. Each role needs one obvious home screen.
4. Depth should exist only when needed.
5. The product should feel smaller than its internal complexity.
6. The interface should guide, not ask the user to understand structure.
7. Real-time visibility matters only if it increases calm and certainty.
8. Memory matters because trust accumulates through history, notes, and payment continuity.

## Owner Interpretation
Owner experience should feel like:

- "I know my dog is okay."
- "I see what happened."
- "I know if I need to act."

The owner should not need to browse a system to find reassurance.

## Walker Interpretation
Walker experience should feel like:

- "I know what is next."
- "I can start quickly."
- "The app supports work instead of creating admin."

The walker should not need to navigate before acting.

## Anti-Principles
Do not optimize for:

- more top-level sections
- more management screens
- exposing backend capabilities just because they exist
- keeping screens alive because they were already built

## Product Test
For any screen or flow, ask:

- Does it lower cognitive load?
- Does it answer the main question fast?
- Is the next action obvious?
- Would removing this screen make the product clearer?
